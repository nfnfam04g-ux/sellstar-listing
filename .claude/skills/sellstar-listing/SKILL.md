# セルスタ出品スキル

eBay の再出品作業を半自動化するスキル。スプレッドシートの完成済み行を読み、セルスタの出品画面へ転記し、
**「下書き保存」まで**を行う。完成版の正本仕様は `出品ツール仕様書.md`（リポジトリ直下、v1.4／付録Cが操作の正本）。
本ファイルはその実行手順を凝縮したもの。齟齬があれば仕様書 付録C・E を優先する。

## 0. 最重要の安全ルール（必ず守る）
1. **絶対に最終の「出品」ボタンを押さない。** ゴールは常に「下書き保存」まで。出品は人が目視後に押す。
2. **二重処理を防ぐ**: 行に着手したら、最初に B列「出品ステータス」を `処理中` に書いてロックする（後述）。
   `処理中`/`下書き保存`/`出品済` の行は処理しない。
3. **入力は読み戻して確認**（read-back）。価格・SKU・コンディション等は入力後に画面値を読み直し、一致を確認する。
4. **失敗しても極力「下書き保存」まで進めて止める**（入った分を残す）。
5. **重要操作の前後でスクリーンショットを取る**（特にエラー時）。
6. 不確実なら止めて `要確認` を記録する。曖昧なまま「出品」へ進めない。

## 2. 起動モード（呼ばれ方で分岐）
| モード | 何をするか |
|---|---|
| **手動（既定）** | 「再出品ツール」シートの **B列が空欄の行を上から順に** 処理（下書き保存まで）。件数指定があればその数だけ。 |
| **単発** | 「○行目だけ」「このSKUだけ」と指定された **1行だけ** 処理。 |
| **自動巡回** | スケジューラ起動。空欄行を順に処理して終了（3時間ごと。1起動＝1巡回）。終了時に稼働ログを残す。 |

判断に迷う指示は、処理範囲（全件か1行か）をユーザーに一度だけ確認してよい。自動巡回時は確認せず進む。

## 4. 処理手順

### 4-A. 全体の流れ（オーケストレーション）
`sheet_io.py`（gspread）でシート、Claude in Chrome でセルスタを操作する。`<venv>` は付録の環境。
1. **対象行の取得**: `<venv>/bin/python sheet_io.py pending` → 出品ステータス空＆ItemURL有りの行リスト（`row_num`）。
   - 単発指定（「○行目／このSKU」）ならその行のみ。手動・巡回は上から順に。
2. 各 `row_num` について:
   a. `sheet_io.py read <row_num>` で全項目を取得（ヘッダー名で解決）。
   b. **ロック**: `sheet_io.py status <row_num> 処理中`（二重処理防止）。
   c. 必須チェック（4-Bの`スキップ`/`要確認`条件）→ 該当すれば status＋error を書いて次の行へ。
   d. セルスタで 4-1〜4-5 を実行（新規出品〜下書き保存）。
   e. **書き戻し**: 成功なら `sheet_io.py status <row_num> 下書き保存`。
      失敗なら `sheet_io.py status <row_num> <区分>` ＋ `sheet_io.py error <row_num> "<コード> <理由>（<項目>）<日時>"`、
      かつセルスタのメモ欄にも同ログ（第5章）。
3. 1巡回の上限（暴走防止）と件数指定を尊重。`ハル`時は停止＋通知（第5章）。

### 4-0. ロック（補足）
- 上記 4-A-b の通り、着手直後に `処理中` を書く。`処理中`/`下書き保存`/`出品済` の行は処理しない。
- ※`pending` は出品ステータス空のみ拾うので、`処理中` を書けば他端末/次巡回と競合しない（付録F）。

### 4-1. 事前
- セルスタにログイン済みであることを確認 → 「新規出品」を押す。未ログインなら **E001（`ハル`）**→巡回停止＋通知。

### 4-2. 新規出品モーダル（実機構成は仕様書 付録G-1）
要素は ref 固定でなく**表示ラベルで探す**。上から順:
1. **出品ストア選択**: プルダウンに `ストア名` の値を選択（ストアごとに設定が変わるため必ずこの値）。
2. **出品方式選択**: `eBayアイテムURL / ID` のままにする（変更不要）。
3. **eBay Item URL / ID 入力欄**（出品方式の下のテキスト欄）: `ItemURL` を **そのままの形（フルURL）で入力**（数値IDに短縮しない・v1.6）。
4. **仕入先（3組。各 URL欄＋ソース種別プルダウン）**:
   - URL: 1=`仕入元URL①` / 2=`仕入元URL②` / 3=`仕入元URL③`（空欄は空のまま）。
   - ソース種別プルダウン: `仕入元①`/`仕入元②`/`仕入元③`（メルカリ/楽天市場/Yahoo!フリマ等）に合わせて選択。
     ※URL貼付で自動判定される場合は選択不要（実機で確認）。
5. **出品テンプレート選択**（`発送方法`(CX) で分岐）:
   - 発送方法 = **エコノミー** → **エコノミー系テンプレート**（実機の `Economy`）
   - 発送方法 = **DHL または FedEx** → **DHL・FedEx系テンプレート**（実機の `DHL fedex`）
   - 状態・価格帯では分けない。実機の選択肢には `新品/中古 DHL`・`新品/中古 エコノミー [価格帯]`・
     `販売価格 2500ドル以上 DDU`・`DHL fedex`・`Economy` があるが、汎用2択（`Economy`/`DHL fedex`）を使う。
     ※初回テストで「この2択でよいか」を画面で確認する。
6. 「出品画面へ」を押す。遷移しなければ最大3回リトライ → 失敗で **E202（`リトライ`→超過で`要確認`）**。

### 4-3. 出品画面の入力
1. **タイトル**（一番上）: `タイトル`。
2. **カスタムリンク**: `検索URL`。
3. **カスタムラベル(SKU)**: `仕入れキーワード`(E列)（v1.6: 旧 C列`SKU` から変更）。
4. **コンディション**: `状態` を見て該当 Condition を選択（参照: `reference/condition-map.md`、カテゴリで表示名が変わる点に注意）。
   - Condition description 欄は「テンプレ選択プルダウン＋テキストエリア」で、UI上**「新品以外の場合のみ記入可能」**。
   - 状態 = New → **Condition description は不要**（触らない）。
   - eBayクローンが Condition を自動設定する（例「目立った傷や汚れなし」→ "Pre-owned - Good"）。原則それを尊重。
   - **中古品（New 以外）のときのみ** Condition description を入力:
     - **日本語のコンディション語句**を取得する。実機では `状態テンプレ`(X) は空のことが多く、**`状態`(W) に語句**（例「目立った傷や汚れなし」）が入る。**X→無ければW** の順で語句を得る。
     - その語句を 別シート「状態　テンプレ」**A列**で探し、**一致行のC列の英文**を Condition description のテキストエリアに入力。
       （実例: 「目立った傷や汚れなし」→ "Item is in good condition with light signs of use. ..."）
5. **Selling Price**: `売値($)`。
6. **ベストオファー**: `Best offer` が ON のとき:
   - ベストオファーにチェック → その下の **オートメーション** にチェック → 指定欄に `拒否価格` を入力。
   - `承認価格` は**入力しない**（不要）。
7. **シッピングポリシー**: `Shipping Policy`(CY列) と**同名のポリシー**をプルダウンから選ぶ（option valueで選ぶと全角空白ズレ回避）。
   - ⚠ **Shipping Policy はセルスタの下書き保存で必須**（空だと「リスト内の項目を選択してください」で保存不可）。
   - **CY列が空/`#REF!` のとき（v1.7・ユーザー方針）**: ブロックせず、**`売値($)` の価格帯に合う暫定ポリシーを選んで下書き保存**し、
     **status＝`要確認`＋`出品エラー`にE302**（暫定で保存・正ポリシー要確認）を記録する。人が最終確認で正しいポリシーに直す。
     （例: $143.99 → `Economy 100-150 +23`。価格帯マップは付録A-4／実機のプルダウン名に従う）
   - ※タイトル等に「ブラックリスト：◯◯」警告（商標ワード）が出た行も `要確認` に含める。
8. **商品説明(Description)**:
   - 右カラム Description のリッチエディタ（**Summernote**）。ツールバーの **`</>`（CodeView/HTMLソース）** ボタンで HTMLモードへ。
   - **`Description`(Z列) の完成HTMLをそのまま流し込む**（生成・組み立ては不要。シートが完成HTMLを持っている）。
     - 実装手順: `$('#description_text_area').summernote('code', html)` で確実に投入できる（検証済み）。長いHTMLはbase64経由でJS注入。
   - `</>` を戻し、内容が反映されたか確認。`Description` が空なら **E502（`スキップ`）**。

### 4-4. 利益計算
1. 上部の「利益計算」ボタンを押す。
2. 価格は既に入っている → **仕入れ値が入っているか確認**。
3. 寸法・重量を入力（値があるものだけ）:
   - 重量=`実重量` / 高さ=`高さ` / 長さ=`奥行き` / 幅=`幅`。
4. **メモ欄**:
   - 名前=`リサーチ担当`。
   - エラーがあった場合は `{リサーチ担当}␣{エラーログ}`（名前の後に半角スペース1つ＋エラー内容）。
5. **DDP対応関税率**: `DDP対応関税率(%)` 欄に `DDP対応関税率`(FE) を参照し、値が空でなければ入力（空欄なら不要）。
   ※「適用税率(%)」は別欄なので触らない。
6. **「利益計算保存」**（緑ボタン）を押して保存 → **「出品画面へ」**（青ボタン）で出品画面に戻る。

### 4-5. 完了（下書き保存まで）
1. 出品画面に戻る。
2. **「下書き保存」を押す**（※「出品」は絶対に押さない）。
   - 新規作成フローのボタン名は「下書き保存」想定。既存編集画面は「更新」表示（G-4で要確認）。「出品」系の語が付くボタンは押さない。
3. 保存後、画面が下書き状態になったか確認（read-back）。ならなければ最大3回リトライ → 失敗で **E902**。
4. 成功したら **`sheet_io.py status <row_num> 下書き保存`** で書き戻す。書込後 `read` で読み戻して確認。
5. エラーがあった場合は第5章に従い記録する（`sheet_io.py status`＋`error`＋セルスタ メモ欄）。

## 5. ステータス・エラー処理（仕様 付録E）
記録は3層に分ける（コードと解説を切り分ける）。詳細・全コードは `reference/error-codes.md`。

> **★ シートへの書き込み手段（実機検証 2026-06-08）**
> - **自動運用は Google Sheets API（OAuth）で書く**のが確実（ユーザー承認済み）。
> - ⚠ **ブラウザの直接入力（type）で日本語をセルに打つのは不安定**（Google Sheetsのグリッドが多バイトを取りこぼす）。
>   ブラウザで書く場合は **既存セルをコピー＆ペースト**（例: 別行の `下書き保存` を copy → 対象B列へ paste）すると確実。
>   名前ボックスのクリック＆navigateも不安定なので、書込はAPIを優先する。
> - **書込後は必ず read-back で確認**（誤入力・空入力を検知）。

- **`出品ステータス`(B列)** … `sheet_io.py status <row> <値>`。区分の日本語だけ: `処理中` / `下書き保存` / `スキップ` / `リトライ` / `要確認`。
- **`出品エラー`列** … `sheet_io.py error <row> "<ログ>"`。コード＋ログ。フォーマット:
  `<コード> <一言理由>（<該当列/項目>）<日時>`  例: `E301 状態「美品」が対応表にない（状態）2026-06-08 14:03`
- **セルスタのメモ欄** … 同じエラーログを複写（利益計算メモに名前＋スペース＋ログ／ブラウザ操作）。

### 回復区分（4種）
| 区分 | 意味 | 動作 |
|---|---|---|
| `リトライ` | 一時的（通信/UI） | 自動で**最大3回**リトライ → 超過で `要確認` |
| `スキップ` | 上流データ未完（必須欄が空など） | 今回は飛ばす。次巡回で再判定（B列=`スキップ`） |
| `ハル` | 続行不能（未ログイン/利用上限） | 処理中の行を下書き保存まで進め、**巡回を停止＋通知**。B列には書かず稼働ログへ |
| `要確認` | データ不正（人が直す） | 入った分まで下書き保存して停止。B列=`要確認` |

`スキップ`(データ未完) と `要確認`(データ不正) を必ず区別する。

## 6. 複数端末・自動巡回時の注意（仕様 付録F）
- 排他は**シート側のロック**で行う（4-0 で即 `処理中` を書く）。端末側ロックは使わない。
- 可能なら別シート「稼働ログ」に巡回ごと `端末名 / 日時 / 処理件数 / 結果` を1行追記（ハートビート）。
- `ハル` や 連続失敗（例: 5行連続 `要確認`）では巡回を止め、ユーザーに通知する。

## 7. 動作確認（ステップ①）で特に丁寧にやること
初回は無人化せず、1行（単発）で通しで確認する。セルスタの実際のボタン名・プルダウン項目・CodeView の挙動を、
このスキルの記述と突き合わせて確認し、ズレがあれば本ファイルと `出品ツール仕様書.md` 付録C を更新する。
セレクタは固定値で決め打ちせず、**画面の表示ラベル/テキストで要素を探す**（UI変更に強くするため）。
